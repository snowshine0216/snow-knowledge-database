### Notes Column

**为什么需要心法**

两种典型失败模式都源于同一个问题：没有"最小完备的锚点清单"。

- **失败模式一：从头到尾读代码**。从 controller 开始逐方法读，读三天还没过完 service 层，读了就忘，没有锚点也没有目标。一周后重新打开，代码又变陌生了。
- **失败模式二：直接让 AI 全盘托管**。`Claude Code: 帮我总结项目` → AI 给漂亮总结；`帮我找改造点` → AI 给 todo list；`帮我写方案` → AI 给方案。照着改上线，出事。隐患在于：AI 只看到了代码，项目历史、对接方约定、隐性限制它看不见，你也没去补。

**八步心法**

| 步骤 | 名称 | 核心动作 | 产出 |
|---|---|---|---|
| 1 | 读 README 和根目录文档 | 看 README + docs/，建立最粗轮廓 | 项目是什么、跑在什么环境、核心概念 |
| 2 | 扫项目结构 | 看目录和包组织（pom.xml/cmd/packages） | 模块地图：分几块、各块职责、核心 vs 边缘 |
| 3 | 找核心入口 | HTTP 服务找 controller+main；定时任务找调度注册处 | 坐标原点：用户到代码的第一个接触点 |
| 4 | 画项目全景 | 架构图 + 模块依赖图 + 核心数据流图 | 把散碎认知拼成图（07、08 讲主题） |
| 5 | 梳理接口和数据模型 | 对外接口清单 + 内部核心数据结构 | 项目的"对外契约"和"内部骨骼"（09 讲主题） |
| 6 | 搭环境跑起来 | 解决依赖/中间件/环境变量 | 能打断点、能看日志、能复现问题（13 讲展开） |
| 7 | 带着需求深挖代码 | 沿调用链路深挖目标模块，每处带"为什么这么写"的问题 | 有目标的代码理解，胜过无目标通读百倍 |
| 8 | 沉淀成 AI 能读的文档 | 写 CLAUDE.md（项目上下文备忘录）+ SKILL.md（可复用模板） | 把脑子里的理解变成 AI 也能看见的资产（10、11 讲主题） |

**三个落地原则**

1. **螺旋不是线性**：八步是锚点清单，不是顺序流水。读 README 时扫了结构、搭环境时发现新接口要回头补清单——来回是正常的，重点是八步最终都走到。
2. **沉淀文档，不是留在脑子里**：人的脑子有极限，AI 也读不到你脑子里的东西。每走完一步，问"这步的产出我写到哪里了"？没沉淀等于没做。
3. **建立锚点，不是读懂**：老项目代码几万行，写过的人换了好几拨，历史细节没人记得全。目标是"足以推进改造的最小理解"——知道核心链路、高风险模块、对外契约、历史坑，这就够了。

**示范项目：Spring AI Alibaba Admin**

- 阿里巴巴官方开源，spring-ai-alibaba 主仓库下的子项目，AI Agent 一站式开发平台
- 技术栈：Spring Boot + React 前后端分离，连 MySQL + Nacos，有 OpenTelemetry 链路追踪，8080 端口
- 选它的理由：形态和公司里典型的企业级微服务一致（多模块 Maven、REST API、中间件依赖），方法论可 1:1 迁移；Apache 2.0 开源活跃，可真实提 issue/PR

### Summary

了解老项目的八步心法本质是一张"最小完备的锚点清单"，解决了两种极端失败模式（无目标通读 vs. 全盘托管 AI）的共同根源。八步不是线性流水，而是螺旋迭代推进的锚点集合；每步的产出必须落地成文档而非停留在脑中；目标是建立"足以改造"的锚点，而非追求完整理解。第二部分接下来五讲将在 Spring AI Alibaba Admin 这个真实企业级项目上把八步逐一跑通。

## Key Takeaways
- 接老项目的失败不在于能力，在于缺"最小完备锚点清单"——既无重点通读，又全盘交给 AI，都是走偏
- 八步心法：读 README → 扫结构 → 找入口 → 画全景 → 梳接口/模型 → 跑起来 → 带需求深挖 → 沉淀 AI 可读文档
- 核心反直觉原则：目标是**建立锚点**，不是读懂。老项目永远读不完，"足以推进改造的最小理解"才是终点
- 产出必须落地文档：`CLAUDE.md`（项目上下文备忘录）+ `SKILL.md`（可复用操作模板），留在脑子里的理解 AI 看不见
- 螺旋而非线性：第四步发现第二步没走扎实，回去补是正常工作方式，不是失误

> 第四步是"画项目全景"：把散碎认知拼成架构图 + 模块依赖图 + 核心数据流图三张图，存入 `docs/`。第八步是"沉淀成 AI 能读的文档"：把前七步的产出写入 `CLAUDE.md`（项目上下文备忘录）和 `SKILL.md`（可复用操作模板）。两者的关系是：第四步产出的图是第八步 CLAUDE.md 的前置资产，图画好了 CLAUDE.md 才能写扎实。
>
> ---
>
> **题目 3 - 引导答案思路：**
> 老项目代码几万行，写过的人换了好几拨，历史细节没人记得全——真正意义上的"读懂"是不可能达到的目标。锚点指的是"改造时能抓住的把手"：核心链路从哪到哪、哪些模块是高风险改动区、哪些接口是对外契约不能随便改、历史上有哪些已知坑。有了这些锚点，即使对整体没有完整理解，也能安全推进改造。
