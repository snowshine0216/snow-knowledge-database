# 了解老项目的八步心法

接手一个陌生老项目时，工程师通常陷入两个极端失败模式：从头到尾无目标通读代码（读了就忘，三天过不完 service 层），或全盘交给 AI 代劳（AI 看不见历史约定和隐性限制，改了上线出事）。两者的共同根源是缺少"最小完备的锚点清单"。这套八步心法就是那张清单——告诉你哪些事必须自己做、哪些事 AI 做、做完每步的产出写到哪里。

## Key Concepts

- **最小完备锚点清单 (Minimum Viable Anchor Checklist)**：了解老项目的目标不是"读懂"，而是建立"足以推进改造"的锚点集合。核心链路从哪到哪、哪些模块高风险、哪些接口是对外契约、历史上有哪些坑——有了这些，即使对整体没有完整理解也能安全改造。
- **八步心法**（螺旋迭代，非线性）：
  1. **读 README 和根目录文档** — 建立最粗轮廓（项目做什么、跑在什么环境、核心概念）
  2. **扫项目结构** — 看 pom.xml 模块划分或 cmd/packages 目录，产出模块地图
  3. **找核心入口** — HTTP 服务找 controller+main 函数，定时任务找调度注册处
  4. **画项目全景** — 架构图 + 模块依赖图 + 核心数据流图，存入 `docs/`
  5. **梳理接口和数据模型** — REST 接口清单（对外契约）+ 核心数据结构（内部骨骼）
  6. **搭环境跑起来** — 能打断点、看日志、复现问题，认知飞跃的关键节点
  7. **带着需求深挖代码** — 有目标地沿调用链路读，每处问"为什么这么写、改了会影响谁"
  8. **沉淀成 AI 能读的文档** — `CLAUDE.md`（项目上下文备忘录）+ `SKILL.md`（可复用操作模板）
- **CLAUDE.md**：项目特定上下文备忘录，把前七步积累的理解写入，让 Claude Code 在后续所有改造中能"看见"这些上下文。第八步前半部分（第 10 讲）。
- **SKILL.md**：把项目里反复出现的操作模式固化成可复用模板，Claude Code 直接调用。第八步后半部分（第 11 讲）。
- **螺旋式迭代**：八步是锚点清单而非顺序流水。第四步画图时发现第二步没走扎实 → 回去补扫结构，完全正常。重点是八步最终都走到，不是顺序。

## Key Takeaways

- 两种失败模式（无目标通读 vs. 全盘托管 AI）都源于同一缺失：没有最小完备锚点清单
- 第四步"画项目全景"产出的三张图（架构图、模块依赖图、数据流图）是第八步 CLAUDE.md 的前置资产，必须先画扎实
- **产出文档化原则**：没沉淀等于没做——每走完一步，立即问"产出写到哪里了"；AI 看不到脑子里的理解
- 老项目的核心真相：永远不会真的读懂一个老项目（写它的人换了好几拨，历史细节没人记得全）；"足以改造"的最小理解才是终点
- 示范项目 [[Spring AI Alibaba Admin]]：Spring Boot + React + MySQL + Nacos，4个 Maven 子模块，形态与典型企业级微服务一致，方法论可 1:1 迁移
