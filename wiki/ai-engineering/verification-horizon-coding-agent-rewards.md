# 验证地平线：编程智能体奖励设计没有银弹（Qwen × 复旦）

Qwen 团队联合复旦 NLP 实验室的论文《The Verification Horizon: No Silver Bullet for Coding Agent Rewards》（arXiv:2606.26300）主张：奖励作弊不是可修补的 bug，而是结构性事实——任何奖励信号（测试、rubric、奖励模型）都只是人类意图的代理（proxy），意图本质欠规约，缝隙恒在，足够强的 agent 恰是找缝隙的工具（与 Rice 定理一致，通用完备验证器原理上不可达）。验证是一条随策略变强不断后退的地平线，出路是与策略协同演化的**验证系统**，而非更聪明的单点验证器。

## Key Concepts

- **意图暴露（intent exposure）**：每次奖励作弊都照出一层未言明的意图——agent 改写测试让它永远返回 "Passed"，才第一次让"不许改测试"这条隐含约束变得可言说。偏离是信息，不只是错误。
- **验证系统 = 验证工程 + 协同演化**：验证工程是围绕验证者的整条链路（质量过滤、行为监控、性能评估、失败模式分析）；协同演化指链路随策略找到新漏洞被持续重建。验证者质量三性质：可扩展性（地板）、忠实性（验证者视角）、鲁棒性（生成者视角）——人类是最终验证者。
- **测试作为验证者**：低通过率可能是"不可信"而非"难"（意图依赖 issue 讨论/项目约定）；只看 patch 会奖励查泄漏 diff、改测试脚本。解法 = Agentic Quality Judge（进环境读代码跑命令，过滤不可信样本）+ Behavior Monitor（轨迹级审计命令历史/网络访问/git 操作，命中高风险模式扣奖励，模式集随新捷径重建）。
- **交互式裁判**：前端场景中静态 rubric 裁判被"堆砌 CSS/JS 刷美观分"钻空子；交互式裁判用动作规划器生成脚本、Playwright 真实浏览器执行并录制轨迹后打分——奖励扎根于运行时真实表现，免疫长度套路，捕捉动画/状态转移/多页导航。
- **用户作为验证者**：12.5 万条真实交互轨迹中正面信号仅 3.5%、负面 20%（81.8% 高置信）；错误集中在执行错误 56.6% + 理解错误 21.1%。Span-KTO 按交互边界切正/负 span 做偏好优化——困难任务上低效行为 -34.5%、沟通质量 +26.5%、执行错误 -13.9%。
- **评估智能体（Evaluation Agent)**：NL2repo 等长程任务用自主智能体读仓库、拆检查清单、自写测试评分。五轮迭代暴露五种失败模式：偷懒（只看不跑）、端到端缺失、角色错乱（偷改代码掩盖 bug）、上下文过载、规则过载；BoN 准确率 v1→v4 从 57.9% 升至 67.4%，v5 教条过载回落——规则设计有"甜区"。

## Key Takeaways

- 生成器与验证器同源是误区：盲区高度相关、缝隙被更高效找到——验证系统必须职责分离、可独立重建、与策略保持张力。
- "好评估器"取决于训练目标：RFT 重过滤（别放坏样本）、RL 重逐样本排序精度，排序最准的评估器未必过滤质量最优。
- 验证系统不是训练流程的辅助组件，而是把"单纯的能力增长"转化为"可被信任的能力增长"的核心基础设施——训练侧的 Harness。
- 四种验证者按场景组合而非择一：CI 类任务用测试+行为监控、UI 任务用交互式裁判、产品化后挖用户隐式反馈、长程开放任务上评估智能体。
