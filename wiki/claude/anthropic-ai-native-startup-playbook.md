# Anthropic AI 原生创业公司手册

Anthropic 于 2026 年 5 月发布了面向创始人的 AI 原生创业公司实用手册（The Founder's Playbook），将创业旅程划分为**想法→MVP→发布→规模化**四个阶段，系统说明如何在每个阶段用 Claude Chat、Claude Cowork 和 Claude Code 放大创始人的杠杆。手册的核心论点是：AI 已经将"谁能创办公司"这件事向所有人开放，但同时也放大了最常见的失败模式——构建比验证更容易，创始人必须主动维护纪律。

## Key Concepts

- **Claude 三形态选择逻辑**：Chat 用于快速对话和单次任务；Claude Cowork 用于文件/系统连接、定时运行、耗时知识工作（相当于 AI 运营团队）；Claude Code 用于智能体式编码开发（代码库访问 + git + plan mode）。三者底层相同，差异在工作空间。

- **CLAUDE.md 架构文档**：MVP 阶段最关键的非代码产物。在 Claude Code 写第一行生产代码之前，先与 Claude 定义架构原则并写入 CLAUDE.md，每次会话开始时提供它、结束时更新决策日志。缺少 CLAUDE.md 会导致"AI 技术债复利"——每个新会话从零推导基础决策，架构漂移逐渐积累成不可管理代码库。

- **AI 技术债 vs 传统技术债**：传统技术债线性积累，可用专门迭代清理；AI 技术债以复利方式增长，因为每次新 Claude Code 会话都会重新做出不一致的基础决策。解法是持久的架构上下文文档（CLAUDE.md）和范围定义文档。

- **Problem-Solution Fit 退出标准**：进入 MVP 之前必须同时回答"是"：①问题真实而具体（谁/多久/如何处理）；②解决方案解决的是验证过程揭示的问题，而非最初假设；③有足够信号证明值得构建（等待确定性本身是失败模式）。

- **Sean Ellis 40% PMF 测试**：对活跃用户问"如果不能用这个产品，会有什么感觉"，超过 40% 回答"非常失望"是有意义的 PMF 指标。PMF 前留存需要创始人持续干预；PMF 后产品"自己完成工作"，增长从"推"变成"拉"。

- **三类可防御护城河**（规模化阶段）：①领域专业知识编码进产品（例：医疗账单 AI 内置 340B 药品计划逻辑，通用 AI 无法复制）；②行为数据飞轮（用户行为信号 → 产品改进 → 更多使用 → 更多数据，具有时间锁定性）；③工作流锁定（客户在产品之上构建自动化和集成，切换成本从产品决策变为完整运营项目）。

## Key Takeaways

- **42% 创业失败因为做了没人想要的东西**（AI 前时代）；Claude Code 让构建更容易，但这个比例只会更高，不是更低——验证纪律在 2026 年比 2016 年更关键
- **"AI 是结构化反方"比"AI 是研究员"更有价值**：让 AI 为想法找支持证据是确认偏误的放大器；让 AI 专门寻找反证才能暴露真正的弱点
- **创始人成为瓶颈的可操作信号**：一小时决定拖了一周、支持请求堆积（只有创始人知道答案）、运营只有创始人想起来才发生——此时需要立即切换到"运营系统设计者"角色
- **规模化护城河叙事要包含数据飞轮的时间戳**："飞轮运转多久、竞争对手今天开始需要多久才能追上"是融资/收购谈判的核心材料
- **Claude Cowork 的正确心智模型**：不是聊天工具，而是可连接 CRM/日历/项目管理的定时运行运营层——"让那些只有因为创始人想起来才会发生的工作自动发生"

|---|---|
