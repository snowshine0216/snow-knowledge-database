Claude Code创始人Boris Cherny在AI Ascent 2026上接受红杉资本Lauren Reeder专访，披露了他本人2026年至今一行代码未手写、每天合并数十乃至150个PR的工作现实。文章系统整理了Boris对"编程是否已被解决"、未来团队形态、SaaS护城河重排序、以及Claude Code自身演进方向的判断。核心论点：模型能力的提升将持续压缩产品层（harness）的必要性，Claude Code未来可能只剩100行代码；而当前大量安全机制（prompt注入防护、命令校验、权限审批）不过是模型能力不足时的临时补丁，终将退出。此文对关注AI原生工作流、Agent编排与Claude产品路线图的工程师和创始人具有直接参考价值。

## Section Summaries

### 1. Claude Code怎么来的

2024年底，Anthropic内部有一个叫**Anthropic Labs**的孵化团队，成员极少，Boris在其中。使命是把模型已具备但尚无产品承接的能力做成产品。最终交付了三件事：**Claude Code、MCP协议、桌面应用**。

Boris使用的核心概念是**product overhang（产品溢出）**：模型能力已超出现有产品的释放边界，大量潜力被白白浪费。当时主流交互还是typeahead（IDE补全），Sonnet 3.5已让这成为可能，但Boris团队想走得更远——不补全，直接让Agent写全部代码。

> "我们一开始就知道产品在六个月内不会有PMF，因为我们是在为下一代模型建产品，这个判断从一开始就是确定的。"

**发布后没有爆发**：前六个月，Boris自己用Claude Code完成的代码比例约10%，增长不成指数。真正拐点出现在**Opus 4发布的5月**，此后每次模型迭代（4.5→4.6→4.7）使用量都陡然上升一次。

### 2. 编程被解决了吗

Boris在台上做了现场调查：约一部分人100%手写代码，另一部分100%用AI写，中间地带最多。他的评价：**"差不多解决了一半。"**

对他自己：**已经解决了。** 他维护的Claude Code代码库是TypeScript + React（选这两个因为训练数据覆盖充分、生成质量稳定）。从2025年10–11月起，模型就能写出100%的代码。他现在每天平均合并数十个PR，状态好时一天150个。

**尚未解决的边界**：大型复杂代码库、模型不熟悉的语言。Boris的回应简单直接：**"等下一个模型就好了。"**

### 3. 他现在怎么工作

Boris大部分工作在**手机**上完成。打开Claude应用，左侧代码标签里同时跑着5–10个会话，每个会话下又有多个Agent。通常同时有**数百个Agent运行**，每晚还有**数千个Agent**做深度异步任务。

**Loop功能**是他最常用的新特性：让Claude用cron调度一个定时重复任务，频率任设（每分钟、每5分钟、每天）。他目前跑着几十个这样的循环，各司其职：

- 监控PR状态、自动rebase
- 维护CI，发现flaky test就去修
- 每30分钟从Twitter抓取关于Claude Code的反馈，聚类整理后推给他

> "他越来越觉得loop就是未来。"

Anthropic同期发布了**Routines功能**——逻辑相同，但运行在服务端，关掉电脑任务照跑。

### 4. 团队会变成什么样

Boris的判断：**全科型人才会大量涌现，但不是传统意义上的全栈工程师，而是跨学科的全科。**

他自己的团队已是如此：Claude Code团队里的**工程经理、PM、设计师、数据科学家、财务、用户研究员**，每个人都在写代码。各有专业方向，但写代码不再是工程师专属技能。

**最佳会计软件的未来作者**，很可能是一个精通会计业务的人——因为业务知识才是难点，写代码已经是容易的部分。

### 5. SaaS会消失吗

Boris分两层回答：

**第一层：商业护城河重排序**
- **切换成本（switching costs）↓**：AI可帮你从一套系统迁移到另一套
- **流程壁垒（process power）↓**：当前Opus 4.7能接受目标、反复迭代直到完成，流程分析和优化能力大幅提升
- **不变的护城河**：网络效应、规模经济、稀缺资源——AI无法改变这些

**第二层：创业公司数量×10**
小团队现在可以构建出原来只有大公司才能完成的产品。大公司要改变内部流程、重新培训员工、克服组织阻力；初创公司从第一天就能用AI原生方式搭建，没有历史包袱。

> "现在是历史上最好的创业时机。"

### 6. 印刷术的类比

Boris平时读两类书：科幻和科技史。他认为当下与历史上一个时刻高度相似——**印刷术**。

- 印刷术出现前，欧洲约10%的人识字，他们的工作是为不识字的贵族阶层读写文件
- 印刷术发明后，仅50年，欧洲出版的文字总量就超过了此前1000年的总和；书价下降近百倍
- 历经数百年，全球识字率从10%升至70%

**软件会走同样的路，但速度快得多。** 写软件的门槛将降低到和发短信一样，人人都能做，但专业工程师仍然存在——就像印刷术普及后仍然有专业作家。

### 7. Anthropic内部和外部的差距

Boris的判断：**模型层面，领先幅度不大**（内部会用未发布版本测试，但这些最终都会对外发布）。

**真正的差距在组织层面：**
- Anthropic内部Claude已渗透进每一个工作环节：SQL由模型写，代码由模型写，整个公司无任何手写代码
- 不同人的Claude实例通过**Slack互相通信**：一个人的Agent遇到问题会自动给另一个人的Agent发消息确认，双方都在循环中运行

> "这不是技术领先，而是组织和流程的领先。这个差距，初创公司比大公司更容易弥合，因为从零开始搭，没有历史负担。"

### 8. Claude Code本身的未来

Boris提出了一个反直觉判断：**Claude Code未来可能只有100行代码。**

随着模型能力持续增强，**产品层（harness）的重要性会持续下降**，因为很多原来由产品层做的事，模型会自己完成。

当前安全机制（防prompt注入、命令静态校验、权限模式、人工审批）都是**模型能力不足时的临时补丁**，一旦模型判断和执行足够可靠，这些机制就会逐渐退出。

**近期推进方向：**
- **Loop一等功能化**：让大规模并行Agent的管理更简单
- **Claude Design**：AI辅助设计工具，Boris认为现在已不错，之后会好很多
- **Computer use**：持续进化
- 接下来几周会有新功能上线（截至2026-05-06）

规划视野：Boris明确表示**只做一周到六个月的规划**，更远的事谁也说不准。

## Key Takeaways

- **Boris本人2026年至今零手写代码**，每天合并数十个PR、状态好时150个——这是模型能力真正落地的实证，不是宣传
- **拐点是Opus 4**，发布前六个月Claude Code仅完成约10%代码，发布后每次模型迭代（4.5→4.7）使用量都出现陡升
- **Loop是工作流核心**：cron驱动的定时Agent循环——Boris同时跑数十个，覆盖PR监控、CI修复、Twitter反馈聚类，每晚有数千Agent做异步任务
- **Harness天花板已出现**：当前安全机制（静态命令校验、权限模式）是模型能力不足的补丁，模型够强后会被移除；Claude Code目标是"只有100行代码"
- **护城河重排序**：切换成本和流程壁垒因AI被削弱，网络效应和规模经济不变；Opus 4.7的持续迭代能力尤其加速了流程壁垒的瓦解
- **全科人才重新定义**：Claude Code团队的PM、设计师、财务都在写代码；最好的会计软件未来的作者可能是会计师
- **印刷术类比**：识字率从10%到70%用了数百年，Boris认为软件普及速度快得多，但专业工程师像专业作家一样仍将存在
- **Anthropic内部领先来自组织而非模型版本**：Claude实例之间通过Slack通信、整个公司无手写代码——这种AI渗透深度是组织差距，不是技术差距

## Insights

- **为下一代模型建产品是Anthropic Labs的显式策略**：PMF延迟六个月被视为设计结果，不是失败信号——这对判断当前"还不好用"的AI产品有直接参考价值
- **Loop = 新型软件架构原语**：cron + Agent的组合让持续异步任务成为工作流默认组件，而非偶发脚本；Routines将这个模式迁移到服务端，意味着个人/团队AI的always-on成为可能
- **手机作为主工作设备的转变**：Boris大部分工作在手机上完成，打破了"重度开发必须在大屏PC"的假设——这暗示Claude的移动端体验优先级可能持续提升
- **"等下一个模型"是合理工程决策**：对于当前模型不支持的场景（大型复杂代码库），Boris的策略是不绕路硬上，而是等模型迭代——这与"尽早用AI"的一般建议形成有趣张力
- **Slack成为Agent间通信总线**：Anthropic内部不同人的Claude实例通过Slack互相发消息确认信息，这是多Agent协作的低成本集成方案，可直接复用
